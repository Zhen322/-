# 字里 · 公众号写作工作台

为汽车与车灯上下游公众号准备，面向整灯厂和上游供应商从业者。程序和资料保存在本机；可通过本机已登录的 Codex 调用 GPT-6 Astra，也支持 Ollama 本地模型和云端 API。

## 打开工作台

双击同目录下的 `start.command`，浏览器会打开 http://127.0.0.1:8765 。首次运行若 macOS 阻止打开，可在终端进入本目录后执行 `./start.command`。工作台绑定本机回环地址。

双击 `open-notes.command` 可用本机 Typora 打开思考笔记。你也可以在工作台「我的思考」里编辑、保存，或者在设置中填写自己已有的 Markdown 文件绝对路径。切换路径不会覆盖原有笔记。外部编辑器保存后，下次生成文案会重新读取最新内容；网页里同时有未保存修改时，会提示冲突。

## 建议从这四步开始

1. **素材库**：粘贴你喜欢的文章正文，上传文档，或输入文章链接导入。来源地址和作者尽量补全。微信网页抓取若遇到验证或正文不可见，复制正文导入即可。
2. **拆解文章**：让模型分析标题、开头、结构、论证机制与适用边界。拆解结果保留在素材详情中，写法卡片进入待审核列表。
3. **写法卡片**：阅读、修改，再启用值得保留的卡片。卡片是后续写作时调用的知识，不会改变模型权重。可以持续积累你的编辑经验。
4. **B · 公众号写作**：填写主题、读者、表达风格和长度，选择参考素材，先整理事实与提纲。查看依据并填写调整要求后，再点击「继续生成并审核」，得到待人工审阅的内容包。

上传文档后，当前版本保存的是提取出来的文字，不保留原始 PDF、Word 文件及其图片、排版。原文件请另外留存；工作台备份包含已经入库的文字资料。

适合第一篇试写的需求：

> 面向整灯厂与上游供应商，写一篇讨论「车灯方案从样件走向量产时，应先问清哪些问题」的公众号文章。用问题清单组织结构，突出跨团队沟通。没有出处的数据、项目进展和法规结论不要编造。

## B · 公众号写作：事实在前，审核在后

### 写作规范与技能

点击写作表单右上角或设置中的 **「写作规范」**，可以直接编辑完整主提示词，选择「日常 Lite」或「深度专题」并保存。默认约 1500 字，开启小范围联网补充资料；本次文章的字数选择、联网开关和具体要求优先。提示词改动只影响之后新建的任务，已经准备好的任务继续使用原快照。

你上传的完整原件在 `data/writing-policy/用户原始提示词.md`，当前生效文本在 `data/writing-policy/主写作提示词.md`。界面可以复制文件路径；也可以在 Obsidian 中将 `data/writing-policy` 文件夹作为仓库打开，编辑并保存主提示词。外部保存后，新建写作任务会读取最新版本；网页同时有未保存编辑时会提示冲突，不自动覆盖。网页保存前会保留旧版到 `history/`；使用外部编辑器修改时，历史由外部编辑器管理，已创建的文章任务仍保留原规范快照。

各环节的方法单独保存在 `data/writing-policy/stages/`：事实整理、角度提纲、正文、标题、事实审核、语言审核、定点修改和发布配套。完整技能入口为该目录下的 `SKILL.md`，参考出处与取舍在 `references/来源与适配.md`。程序的初始规范模板保存在 `writing-skills/automotive-wechat-editor/`；更新程序不会重置已有的个人规范。

- **日常 Lite**：采用汽车技术内容的「现象、机制、实际影响与限制」，按用户指定的标题、开头、分论点和结尾组织。
- **深度专题**：在日常规则上增加证据分层、至少两种反方条件和图文对应，适合路线比较与复杂产品分析；不会自动增加篇幅。
- **正文与审稿**：借鉴 WeWrite 的任务、主张、来源与改后复核。仍保留本平台的提纲确认和两轮修改上限；没有安装 WeWrite CLI。
- **范文、标题、语言**：提取范文表达方法，标题保持真实信息边界，语言审核删套话和重复。第三方人设、私人路径、AI 检测率目标、固定五张图及合成案例均未导入。

新生成的文章增加 **「发布配套文案」**：已审推荐标题之外的四个备选标题、摘要、封面文案、封面配图提示词与分享推荐语，支持单项或整包复制，并进入待审包导出。配套只依据最终正文生成，进行同次自查及原句、数字和阶段检查，仍须人工核对；没有经过正文那两次独立审核。核心证据缺失或正文仍有关键问题时，会说明原因并暂不生成配套。手工修改标题或正文后，旧配套会标记过期。

这些规范已接入 **本地 B 流程**。在本机修改提示词不会自动修改云端 Coze 项目；Coze API 仍使用其已部署的提示词与流程。完整主提示词要求的联网、读取与入库动作，以实际工具执行结果为准，不会仅因提示词写了某个动作就显示成功。

保留原来的主题、素材、笔记和写法卡片入口，分成两次手动执行。第一步完成后会停在「待确认」，不会自动继续消耗模型额度。写作任务保存在本机，关闭页面后可以重新打开。

1. **整理事实与提纲**：读取这次任务及准备时的最新笔记；开启联网时先补充相关公开资料。整理事实卡，保存来源编号、原文摘录、企业名称、数字单位、时间、事件状态与不确定性。再从已启用的写法卡片和本次全文素材中匹配相关写作案例，确定文章角度、分论点与对应事实。
2. **查看并继续**：检查事实卡、证据缺口、案例与提纲，在调整要求里写下本次编辑意见，再点击「继续生成并审核」。正文先生成，标题根据正文另行生成，随后分别做事实审核和语言审核。最多进行两轮定点修改，保留修改前后内容与理由，并再次审核。

准备阶段保留了本次资料快照。继续时沿用该快照，方便追溯依据；这期间若更新了笔记或素材，要使用新资料请重新整理一次。写作案例用于借鉴组织和论证方法，相关性排序不代表爆款排名，未提供的热度仍未知。事实卡中的「有原文依据」只表示能追溯到提供的资料，不等同于独立核实事实。

写作要求是：标题有具体信息点、利益点或疑问；开头尽快进入新闻变化、读者痛点或具体矛盾；正文每个分论点有事实、案例或明确推理支撑；结尾回到从业者的实际影响。结构可以复用，措辞不照搬案例。

- **事实审核**：逐项检查企业名称、数字及单位、事件时间与状态，特别区分「展示、定点、计划量产、量产、交付」，也检查是否把「拟修订」写成「已经实施」。标题必须能由正文和事实卡支持。
- **语言审核**：检查没有具体信息的背景句、套话、重复总结与无依据的情绪判断。每条问题列出位置、原句、修改理由和建议，不能用一句整体评价代替审核。
- **有限修改**：只替换能准确定位的问题文字。两轮后仍有关键问题、审核返回异常或定位失败时，保留现有草稿并交给人工处理，不无限重写，也不把审核失败显示成通过。
- **待审内容包**：保存正文、标题、事实卡与来源、案例、提纲、两遍审核和修改记录。即使暂未发现问题也仍待人工审阅，不自动发布。手动修改标题或正文后，原审核需要重新人工核对，不能作为修改后版本已经通过的依据。

此流程会按节点调用当前配置的模型，因此比原来一次生成需要更多时间和使用额度。界面显示当前阶段。单次模型费用没有真实账单时仍为空，不估算为零。第一版使用本地持久化的两次手动执行，尚未接入 Coze 的工作流中断与恢复接口。

## 把 Coze 选题交给写作助手

首页的选题入口保留人工判断：先查看候选选题、理由及来源，再选中一个题目。选择只填写写作要求，不自动生成文章，也不自动把全部选题提交给模型。

**手动导入**：把 Coze 的实际输出粘贴进「从 Coze 选题导入」，支持文本和 JSON。工作台整理为可选择的卡片，保留原始输出；可调整题目与写作方向，再带入本地 B 流程。来源、热度或事实未核实的部分仍需核查。

**日常使用（两个现成助手已配置）**：

1. 在首页填写可选的「研究方向」，点击「获取 Coze 选题」。留空时使用选题助手的默认方向。
2. 等待候选选题返回，选择一个题目，按需要修改标题、方向和理由，点击「用这个选题写稿」。
3. 确认目标读者和字数（默认约 1500 字），可补充自己的观点、资料或链接，再点击「确认交给 Coze 写稿」。平台只提交这个选题。
4. 生成完成后，正文、标题备选、摘要、封面与转发文案、来源及编辑备注保存在本地草稿。原始接口结果保留在调用记录，可从「接入与历史」重新打开，不会重复生成。

这条快捷链路调用你已经部署的两个 Coze 助手，使用它们云端现有的模型、提示词和资料库；不会自动改成工作台的 GPT 模型。只有本次选题和你在确认表单里明确填写的内容会随请求发送，本地私人笔记和写作规范不会自动附加。返回草稿标记为「Coze 原稿 · 待人工审阅」，不能视作已通过本地 B 的独立事实与语言审核。没有真实返回的模型费用和生成耗时留空。

**迁移或更换 API**：两个分享链接作为对应项目入口保留，但预览链接本身不能代替可调用的 API。请在各自 Coze 项目的「部署」页面查看部署记录，找到 API 请求示例及接口说明；将真实部署 API 基址及对应 Token 填入工作台的 Coze 接入设置，不要把 Token 发到聊天或填写在文章里。

先保存「选题助手」和「文案助手」各自的配置，再读取各自的真实输入参数。日常使用快捷按钮即可；高级参数表供你检查和手动执行其他接口输入。快捷入口在每次提交前核对实际字段合同，发现云端参数变化会停止提交，需更新映射后再使用。文案快捷入口固定执行 `write_article`，不会调用云端的文章入库、标题入库或导出分支。

第一版支持扣子编程工作流部署的 `https://子域.coze.site` 基址：先读取 `/graph_parameter`，再通过 `/async_run` 提交一次任务，保存远端任务编号，持续查询 `/task/{task_id}`。暂不支持自定义域名、旧版 Bot/低代码工作流协议或工作流节点的暂停交互。保存配置、成功读取参数、工作流调用完成是不同状态；没有实际地址和 Token 时不会显示已经接通。

Coze 调用可能消耗你的扣子额度。提交超时不代表远端未执行，平台不会自动重新提交。有远端任务编号时，网络中断或本地服务重启后，可在 API 执行记录点击「继续查询已有任务」；它只查询原任务，不生成新任务。查询期限取远端截止时间与本机最多 24 小时的较早者。远端任务运行时不要重新部署或停止 Coze 实例。如果远端已完成而本地保存失败，选择重试本地保存即可，不会再次调用 Coze。文案结果读取实际 `article` 正文字段，也兼容 `markdown`；外部下载链接只保留在原始返回中，不代替本地正文。Token 仅保存于本机单独的凭据文件，不回显，也不收入备份；恢复备份后需要重新填写。

## 给草稿找配图

在写作工作台勾选「成稿后找配图」，选择 5—8 张（默认 6 张），生成文字后会继续寻找图片。已有文章可以在「文章草稿」中打开，点击「联网找配图」；如正文有修改，先保存最新版再搜索。

平台会根据文章内容提炼检索词和配图位置，联网寻找真实图片，并展示预览、来源页面、建议图注和插入位置。可打开原图及来源，或导出配图清单。结果会随草稿保存；正文修改后，旧结果可能不再适用，可重新查找。

搜索只发送从草稿提炼的关键词，全文由你选择的写作模型处理。图片搜索使用现有 Tavily 设置，免密额度不足时会提示。若未找到足够可追溯的图片，会显示实际数量；配图搜索失败不影响已经保存的文字草稿。

推荐图不等于已获转载或商用授权，发布前需到来源页核实使用条件。当前保存的是配图清单和图片链接，不自动下载原图；来源网站失效或限制外链时，预览可能无法显示。备份保留配图记录，原图需自行按许可保存。

## D · 数据复盘

先记录真实的发布数据，再决定下次尝试什么。侧栏「D · 数据复盘」支持手动录入，以及 UTF-8 CSV、JSON 批量导入；可先下载 CSV 模板填写。第一版不自动采集公众号后台数据。

每条记录关联一个文章 ID，可选择工作台已有草稿，也可记录外部创作的文章。记录包括发布时间、选题类型、采用标题、标题结构、封面模板、阅读与互动指标、统计时间、人工修改内容与原因，以及生成耗时和模型费用。数据来源与备注用于说明后台口径或特殊情况。

- **未知留空**：空指标不是零；只有后台确实显示为零时才填写 `0`。`10万+` 等非精确值不要换成猜测的整数，可原样保留在备注中。模型费用没有账单或用量依据时也留空，会员调用不自动记为免费。
- **保留统计快照**：同一文章后续补录 24 小时、48 小时等数据时，用「新增统计」，保持文章 ID 一致，填写新的统计时间。复盘按文章去重，采用最新统计快照，不把累计阅读量重复相加。修改已有记录会保留修改前的版本，并防止过时页面覆盖新版本。
- **分清统计窗口**：填写发布时间与统计时间才能计算观察时长。复盘将观察时长按一小时区间分组，缺少时间的记录不参与窗口比较；不同窗口不会混成一张效果排名。
- **关注变化单独记录**：账号关注净变化需要同时记录账号统计窗口。该值只说明账号在这段时间的变化，不自动归到某篇文章，也不会在多篇文章之间相加。
- **耗时和费用有依据**：新增草稿记录生成耗时；B 流程记录正文与标题节点的合计模型耗时，不包含事实整理、审核、人工确认等待或后续配图，另保存流程内模型耗时供检查。旧稿没有记录的耗时留空。费用可按实际账单手动填写金额、币种与来源，不按模型名推算，不混合人民币和美元。

点击「生成复盘」后，输出已观察到的事实、当前数据的局限，以及可尝试的调整。第一版使用本地规则，不调用模型补数字，不自动训练模型，也不自动改写你的写法卡片。建议是下一轮待验证的尝试，例如在相近选题和发布时间下只调整标题结构，并统一在发布后 24 小时记录数据；不据此宣称某种标题导致阅读上涨。

批量导入会先校验整批数据；格式、重复记录或时间有误时，整批不写入。相同文章 ID 与统计时间不会重复导入。JSON 导出包含修改历史，CSV 适合表格查看；将导出文件重新导入不是完整备份恢复，完整恢复请使用工作台 ZIP 里的数据库。手动备份包含发布数据及其历史，不依赖网页才能查看。

## 联网搜索与热度

平台通过 Tavily 搜索公开文章。官方提供有额度限制的免密搜索；若达到限额，在「设置」填入自己的 Tavily API key。联网搜索会向搜索服务发送搜索词；个人笔记不会作为全文发给搜索服务。

公众号限定搜索只表示寻找相关域名的结果，不代表结果一定齐全，也不代表按阅读量排序。公开搜索常无法返回文章的真实阅读、点赞与收藏数据。平台对未知值留空，并支持手工补录数值、数据来源与记录时间；有记录后可以在素材库排序筛选。若需要持续自动获取跨账号热度排名，还需要可用的授权数据服务接口，本版未接入付费数据平台。

抓取成功的完整正文可拆解；只得到搜索摘要的结果会标识为摘要，不把摘要冒充全文。链接失效、验证页或付费内容不会绕过限制读取。

## 模型设置

- **Codex 会员 · GPT-6 Astra**：在「模型与设置」选择 Codex 会员，模型填写 `gpt-6-astra`，保存后点击「测试已保存的模型」。工作台调用本机官方 `codex exec`，复用 CLI 已保存的 ChatGPT 登录，不需要 API 密钥，也不会读取或复制登录令牌。此方式消耗同一账号的 Codex 使用额度，模型权限和限额取决于你的账号；额度用尽后需等待恢复或自行调整套餐。
- Codex 模式下，界面和资料仍保存在本机，参与本次任务的笔记、素材和写法卡片会发送给 OpenAI 处理。文字处理以只读、临时会话运行，并关闭浏览器、命令执行、插件等无关工具。联网找文章仍使用工作台的搜索功能。
- 如果提示未安装或未登录 Codex：打开已安装的 ChatGPT/Codex 应用，或在终端执行 `codex login` 完成官方登录，再回到工作台测试。工作台自身不收集会员密码或登录令牌。
- **本地模型**：默认 Ollama，地址 `http://127.0.0.1:11434`，模型 `qwen2.5:latest`。本地生成速度和效果取决于电脑与模型。
- **云端模型**：选择兼容接口，填写服务商给出的 API base URL、模型 ID 与密钥。选择云端后，本次用到的笔记、素材与写法卡片会随提示词发送给该模型服务商。
- 密钥只在本地设置页填写，不需要发到聊天里。设置文件以本机账户可读写权限保存，不是加密保险库；备份或分享程序时不要带上它。

## 数据位置与备份

`127.0.0.1:8765` 是本机程序的入口，不是存放资料的互联网网站。关闭浏览器、关机或程序停止后，已经保存的资料仍留在电脑里。重新运行 `start.command` 即可打开；也可以在本机 Chrome、Safari 等浏览器访问该地址。

这个 `wechat-writer` 文件夹包含整个项目：`app.py`、`engine.py`、`image_engine.py`、`writing_engine.py`、`writing_store.py` 等是程序，`static/` 是网页界面，本文是使用说明。日常资料在 `data/` 内：思考笔记位于 `data/notes/`，文案导出位于 `data/drafts/`，写法卡片位于 `data/cards/`，事实卡和审核内容包位于 `data/writing/`，选题批次位于 `data/topics/`，发布数据位于 `data/performance/`；结构化素材、写作任务、拆解、卡片、草稿和 Coze 调用结果还保存在 `data/workspace.sqlite3` 数据库中。备份另外将 Coze 已保存的接口结果导出到包内 `data/coze/`。

**手动备份**：保存当前编辑、等待生成结束后，双击 `backup.command`。它会在项目旁边的 `wechat-writer-backups/` 文件夹生成一个带时间的 ZIP，含程序、文档、数据库、当前笔记、完整写作规范与技能来源，以及无需运行平台就能阅读的 Markdown 素材、卡片和草稿。备份可以在服务运行时进行，使用 SQLite 在线快照；每次生成新文件，不覆盖旧备份。外部配置的笔记也会收入包内，恢复后采用包内路径。网页尚未保存的输入不在备份中。

**恢复或搬家**：把 ZIP 解压到新文件夹，查看包内 `备份恢复说明.txt`。先确认旧服务已停止，再运行解压后的 `start.command`；新电脑需要 Python 3.11+，Codex 模式需重新安装、登录官方客户端。运行环境、API 密钥和会员登录凭据不会被打包。备份资料可以直接用文本编辑器阅读，不依赖会员或模型服务。

此功能是手动备份，尚未设置定时备份。本机副本不能防止硬盘损坏或电脑丢失；请把 ZIP 再复制一份到移动硬盘或自己的备份盘。若手工复制 `data/` 文件夹，应先停止程序，并额外备份外部笔记。

生成时会记录所用素材、笔记版本和模型，方便回看依据。正文中的技术指标、法规条款与供应链结论仍需回到原始来源核实；草稿供编辑，平台不会自动发布公众号。

当前版本按完整笔记参与写作，并对本地模型的上下文做保守预算检查。笔记、素材和卡片合计过长时会明确提示，避免悄悄遗漏；可以减少本次引用的素材，或在设置里选择一份聚焦当前主题的笔记。它目前不是一个可无限扩展的大规模知识库。
